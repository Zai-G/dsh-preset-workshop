## 为什么需要它

**您发给 Agent 的一句话，只是模型输入的一部分。**

一次 Agent 请求还可能包含系统提示词、工具名称与定义、技能目录、工作区指令、运行环境、会话历史和工具结果。这些内容共同影响模型如何理解任务、选择工具、组织回答和塑造它的工作方式。

以我们的一次观察为例：在没有额外安装技能和插件的 DSH 环境里，用官方标准预设发送一句「你好」，请求中带着 **32 个工具定义，约 8.5k token**，以及一整套面向编程的系统指令。写代码时这很合适；可如果您只是想查一份资料、改一段文字、讲一道题，大部分工具都用不上，但这些内容却每次都随请求一起发出。

例如，您希望 AI 解释一道题，但当前环境带着大量编程指令、终端操作说明和开发工具。这些能力是否适合这次任务？您希望它先讲概念、举例引导，还是直接动手处理文件？这些选择可以体现在整个工作环境里。

预设工坊把这些选择放到一个可视化界面里：

| 👁 看清 | 🎛 调整 | 📦 复用 |
| :--- | :--- | :--- |
| 查看提示词、工具、技能目录与环境信息 | 按任务选择能力，编辑工作要求，观察上下文规模 | 保存多套预设，在不同任务中使用，也可以导出分享 |

### 您可能正需要它

| 如果您想… | 预设工坊提供 | 从这里开始 |
| :--- | :--- | :--- |
| **看清 Agent 实际收到了什么** | 发送前预览系统指令、可见工具、技能目录、环境与 AGENTS 指令；生成预览不调用模型 | [请求组成可视化](#请求组成可视化) |
| **按任务选择工具** | 每个工具单独开关，按预设管理 MCP 服务与技能 | [工具按需选择](#工具按需选择细到每一项) |
| **控制每次请求里可控部分的规模** | 调整前后都能看到按字符数估算的 token 数 | [上下文开销](#观察并调整上下文开销) |
| **不再每个会话重复交代同样的要求** | 把回答方式、判断标准写进人设和全局 AGENTS 指令，随预设保存 | [提示词编排](#提示词与工作要求编排) |
| **保存、切换、分享顺手的工作方式** | 多套预设互相独立，通过 DSH 原生预设选择器选用；支持 JSON / YAML 导入导出 | [多预设保存与分享](#多预设保存与分享) |

同一个人常常会同时有好几个这样的需求。从任何一个入口开始都可以。

## 五分钟完成第一套预设

下面以「联网调研」为例。安装后进入 **设置 → 预设工坊**。

**1. 新建预设**
在「预设方案」中点「新建」，填写显示名称（如 `联网调研`）和预设 ID（如 `web-research`）。ID 创建后不可修改；名称和描述以后可以随时改。

**2. 只留这项任务要用的工具**
新预设默认带 8 个基础工具。切到「工具」分段，在「内置」里关掉调研用不上的终端和文件工具，保留 `web_search`、`web_fetch`、`ask_user_question`。标题会显示「已启动 N 个工具」，「预设方案」下方的预览卡会同步更新估算值。

**3. 写下这类任务的做法**
在「提示词」分段的人设卡里，把默认的 `You are a helpful assistant.` 换成您的要求，例如：

```text
你是资料调研助手：信息给全，冗余删净。
先给结论，再列依据和来源。
只搜需要的，抓权威来源。
查完就答，不重试不多搜不反问。
依据标证据等级；查不到不编。
```

用自然语言写就行，不需要模板语法。「宿主」卡把人设以外、由宿主与插件注入的内容分成 System 与 User 两层，与任务无关的段落可以关闭。

**4. 发送前先看一眼**
点预览卡右侧的「查看」，切到「最终提示词」：人设是否在最前面，工具是否只剩您选的那几个，工作目录与环境信息是否正确。生成预览不调用模型，可以反复调整、反复查看。

**5. 保存并选用**
点「保存方案」，状态变为「已保存」。然后**新建一个会话**，在 DSH 原生预设选择器中选「联网调研」，正常提问即可。

> 工坊里的预设选择器只用来切换**编辑对象**。一个会话实际使用哪套预设，由 DSH 原生选择器决定；只有新建或尚未开始的空白会话可以选择预设。

用顺手之后，可以照同样的思路为写作、学习、编程等任务各建一套。

## 可以怎样搭配

以下是可自行搭配的用法示例；工具、技能和外部服务的可用性取决于您的安装环境。

| 您想做什么 | 可以怎样搭配 |
| :--- | :--- |
| **轻量聊天** | 关闭不需要的工具和技能，保留称呼、语气、回答长度等对话要求 |
| **学习与学科作业** | 以讲解、推导、核查为核心设置人设；按题目需要保留搜索、阅读或计算能力 |
| **写作** | 调整创作、叙事规则与全局指令，选择创作需要的工具，保存受众、文风、引用和交付格式要求 |
| **资料整理** | 保留搜索、网页抓取及必要的文件工具，绑定资料处理技能 |
| **编程协作** | 终端、文件读写与编辑、项目技能；按任务决定是否增加子代理等能力 |
| **专项工作流** | 通过 MCP 接入需要的外部能力，只开放任务相关工具，保存固定的处理步骤与检查标准 |
| **提示词研究与协作复用** | 保存不同上下文组合，分别试验效果；把选定配置导出给他人复用 |

这些配置需自行创建，插件未预置这些模板，也未内置效果评测。分享文件只含配置，接收方仍需具备对应工具与可解析的技能来源。

## 能做什么

| 能力 | 您可以控制的内容 |
| --- | --- |
| **🗂 预设管理** | 新建、改名、修改描述、启停、删除、恢复默认；每套配置独立保存，ID 创建后固定 |
| **✍️ System 编排** | 编辑人设；编辑、关闭、排序 DSH 宿主注入的系统段，第三方插件注入的系统段；添加自定义内容，查看变量实际值 |
| **📋 AGENTS 指令** | 按预设覆盖或关闭全局 AGENTS 指令；同时支持 DSH 与共享 agents 目录的全局文件，不改原文件；无文件也可填写。目录指令由宿主加载、只读可关，与全局合并为一条消息发送 |
| **🧰 工具选择** | 所有工具逐项启用；扫描官方能力与已注册第三方工具；重型能力按需挂载来源 |
| **📝 工具如何被理解** | 修改工具和参数的描述文字，保留调用名、参数类型、必填项与结构约束，不改变工具实现 |
| **☁️ MCP 服务** | 按预设隔离 MCP；查看官方资源工具与服务器工具，逐项开关；可创建、编辑、删除 stdio 或 streamable-http 服务器 |
| **📚 技能绑定** | 可逐项选择、全选或不选；查看来源、描述、原文与加载补充，不改技能文件 |
| **👁 请求组成预览** | 查看 System、可见工具、技能目录、AGENT、时间与时区及实际权限策略，按所选会话或目录求值 |
| **📦 配置分享** | JSON/YAML 导出当前或全部预设；导入时处理 ID/名称冲突，可确认覆盖或改名 |
| **↩️ 会话回退** | 停用或删除前检查引用并迁移到工坊内的回退预设；保留消息历史，失败保留原预设 |

界面跟随宿主语言与明暗主题，支持窄面板与折叠偏好；插件仅管理自己创建的预设，不改写官方预设或其他插件的业务配置。

## 功能

设置页把配置分成提示词、工具、MCP、技能与兼容五个分段，顶部的分段切换一次只显示一类；「预设方案」与预览卡始终在页面上方。

### 请求组成可视化

「预设方案」下方的预览卡直接显示当前规模，点「查看」打开预览窗口。窗口内分两个分段：

- **工具与技能**：当前启用的工具、MCP 工具和绑定的技能；
- **最终提示词**：按以下顺序展示宿主能取到的内容。

```text
System · 系统指令
├─ 人设
└─ 宿主 / 插件系统段、自定义段

User · 会话上下文
├─ 用户消息（占位）
├─ AGENTS（全局与目录由宿主渲染器合并为一条）
├─ 工作目录
├─ 环境（权限策略）
├─ 技能目录
└─ 时间与时区

工具 · 顶层用途（完整定义另行随请求发送）
├─ TOOL
└─ MCP（按服务器分组）
```

预览窗口把摘要、预览环境与工作目录固定在上方，正文只在窗口内滚动；默认使用当前打开的会话环境，也可以换成其他会话或指定工作目录，没有会话时使用宿主的新会话默认权限。只显示有内容的分组。

**预览不等于抓包。** 它不包含会话历史，也看不到代理转发层或供应商额外添加的内容（例如 `billion-context` 在转发层加入的压缩指令，未向 DSH 暴露可读接口）。这些内容仍会进入上下文，只是工坊读取不到。

### 提示词与工作要求编排

每套预设可以分别设置：

- **人设**：定义任务定位、回答方式和判断标准。支持宿主已注册的 `{{变量名}}`（如 `{{cwd}}`、`{{model}}`），可以查看它们当前的实际值；`$ENV` 形式不会被替换。
- **系统段**：宿主和插件暴露的可调整段落可以编辑、开关，并通过拖拽或方向键排序；也可以新建自定义段。
- **AGENTS 指令**：为当前预设单独设置长期要求。它只覆盖本预设，不改写原始 `AGENTS.md` 文件；没有全局文件也可以填写。目录级 `AGENTS.md` 由 DSH 按工作目录自动载入，这里只读展示但可以关闭；两者由宿主渲染器合并成一条消息发出，改动后以一条更新说明同时替换。
- **工作目录**：默认注入，可以按预设关闭，只影响这一套预设；重新开启后读取当前会话目录，重置预设即恢复默认。
- **时间与时区**：每套预设可以单独开关官方的时间注入。

### 工具按需选择，细到每一项

默认从 **8 项基础工具**起步，每项都可以开关：

| 能力 | 工具名 |
| :--- | :--- |
| 终端命令 | macOS / Linux：`bash`；Windows：`pwsh` |
| 文件读取、编辑、写入 | `read`、`edit`、`write` |
| 联网搜索、网页抓取 | `web_search`、`web_fetch` |
| 询问用户、任务清单 | `ask_user_question`、`todo_write` |

工坊会扫描宿主提供的官方能力与已注册的第三方工具，逐个列出隔离探测到的工具，供您按需选择；重型能力只在启用时按需挂载所需来源，没有包级开关。选择非默认来源时，卡片下方会标出该来源。

关闭工具后，其定义会从当前预设的模型可见工具列表中移除，关联使用指令也会相应调整；多个工具共用的指令，会保留到最后一个相关工具关闭。

同一个工具名可能由多个来源提供。工坊最多列出两个同名候选：选中来源作为主卡，可以直接关闭；其他候选只读，点开只看得到它的 schema。schema 完全一致的候选会被过滤，避免只差描述文字的重复项。

需要进一步调整时，可以编辑工具 JSON 中的**描述文字**，包括工具用途和参数说明。调用名、参数名、类型、必填项及结构约束受到保护，校验失败会阻止保存。

启动时会完成一次扫描，并跟随宿主工具注册变化更新；「兼容」分段另提供手动扫描和可选定时扫描。第三方工具需要先由来源插件实际注册，才能被工坊发现和选择。

### MCP 服务也按预设组织

MCP 是让 Agent 连接外部工具与服务的通用协议。您可以借助相应服务器接入检索、文档、数据等能力，具体功能由服务器提供。

预设工坊支持：

- **发现全局 MCP**：识别宿主已注册的全局 MCP 工具，单独归入 MCP 区域，并按服务器展示。
- **为当前预设创建 MCP**：新建、编辑、删除服务器，支持本地 `stdio` 与远程 `streamable-http` 基础配置。
- **逐工具选择**：同一台服务器提供多个工具时，可以只开启其中需要的几项，并调整允许修改的描述文字。
- **检测连接**：服务关闭时也可在临时上下文中检测并读取工具数量，不启用服务、不调用工具、不保存配置；`stdio` 连接超时 120 秒、`streamable-http` 30 秒，超时后自动清理，结果区分超时与连接失败。
- **查看可用状态**：保存后在后台连接，显示连接中、已连接或失败状态；无响应时自动超时清理，删除连接也不必等待网络收尾。连接未就绪时保留配置，已保存工具不可用时如实显示状态。

在 A 预设里创建的 MCP 属于 A，不会被 B 预设的全局扫描收进去，也不会改写宿主全局 MCP 配置。

官方资源工具 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` 同样可以分别选择；它们的可用性取决于宿主是否存在相应 MCP 资源服务器。

### 技能按任务绑定

为每套预设选择需要的技能。

您可以查看技能来源、描述、正文和加载后的补充内容。技能目录提供名称与摘要，正文及来源追加的内容在调用技能时加载，便于区分“模型先看见的目录”和“使用技能后获得的具体指导”。

绑定复用真实技能来源，不复制或改写技能源文件。

关闭 Skill 工具后，绑定技能的目录不会进入 User 上下文；仍可手动提供技能路径。

已绑定技能无法加载时，预览会提示缺失项，并阻止缺少所选技能的请求继续发送。上下文压缩后，仍启用的技能目录与全局 AGENTS 会重新进入后续请求。

### 观察并调整上下文开销

预览卡显示 `N 个工具 · N 个MCP · N 个技能 · 约 min–max token`，编辑后约半秒内刷新，方便比较调整前后的规模。

- **计算方式**：System、完整工具定义、运行环境、技能目录、全局 / 目录 AGENTS，以及所选会话中可读取的时间和插件提示；CJK 字符按每字 1–2 token、其他字符按约 4 字符 1 token 估算，给出区间而非单个数字。
- **不包括**：对话历史、技能正文、工具结果和模型输出。
- 它不是分词器结果，也不是用量统计。实际费用还取决于模型价格、缓存命中、对话长度、输出和调用次数；频繁修改提示词或工具列表还可能降低缓存命中率。插件不承诺任何固定的节省比例，请以供应商记录为准。

### 多预设保存与分享

每套预设独立保存名称、描述、人设、系统段、工具选择与描述、MCP 配置和技能绑定。名称与描述会同步到 DSH 原生预设选择器。

支持 **JSON / YAML 导入导出**。

您可以把常用工作方式分享给朋友或协作者。分享文件只含配置，接收方仍需具备对应的工具插件、技能来源和 MCP 运行环境。

## 安装

预设工坊需要 **DeepSeek Harness 桌面端或 `dsh web`**，在宿主的设置页中运行。

### 方式一：在 DSH 界面安装

1. 打开 DSH 的「插件」页面，点击「添加插件」。
2. 输入 `dsh-preset-workshop`，完成安装。
3. **重启 DSH**，然后进入 **设置 → 预设工坊**。

### 方式二：使用命令行安装

根据您使用的入口，执行对应的一条命令：

```sh
# 官方桌面端
dsh plugin --profile desktop add dsh-preset-workshop

# dsh web
dsh plugin --profile web add dsh-preset-workshop
```

安装后，桌面端请完全退出并重新打开应用；Web 用户请重启 `dsh web`。

<details>
<summary><b>从 GitHub 或本地目录安装</b></summary>

以下以桌面端为例，Web 用户将 `desktop` 替换为 `web`。

从 GitHub 安装仓库中的版本：

```sh
dsh plugin --profile desktop add github:Zai-G/dsh-preset-workshop
```

也可以在仓库地址后添加 `#<commit>`，固定到指定提交。

从本地完整插件目录安装：

```sh
dsh plugin --profile desktop add "/absolute/path/to/dsh-preset-workshop"
```

本插件使用原生 JavaScript ESM，无额外前端构建步骤。实际功能取决于所安装提交或本地目录中的版本。安装完成后重启对应的 DSH 入口。

也可以在 DSH 的 Creator 模式中，请 Agent 使用宿主 `plugin_manager`：

```json
{
  "action": "install_bundle",
  "target": "dsh-preset-workshop"
}
```

此方式安装到当前 profile。管理工具返回 `application: applied` 表示 Host 已应用，`restart-required` 表示需要重启；失败或警告按返回诊断处理。

</details>

### 更新

在安装时使用的同一 profile 中执行，例如：

```sh
dsh plugin --profile web add dsh-preset-workshop@latest
```

桌面端将 `web` 换成 `desktop`，并先完全退出应用。更新后重启对应 DSH 实例。升级前可导出预设备份，并查看 [更新日志](https://github.com/Zai-G/dsh-preset-workshop/blob/main/CHANGELOG.md) 中的兼容性说明。

安装与更新由宿主管理，请勿手写 profile 配置。

## 生效与边界

对于正在使用工坊预设的会话，许多调整可以在后续请求中生效：

| 修改内容 | 生效时机 |
| :--- | :--- |
| 人设、系统段、工具使用指令及顺序 | 下一次模型请求读取最新保存配置 |
| 已挂载且来源／参数结构匹配的工具开关与描述 | 下一次模型请求；宿主其他限制继续有效 |
| 技能绑定 | 下一次技能目录发布与技能加载 |
| AGENTS 指令（全局 / 目录） | 改动后的下一次请求以一条更新说明整体替换先前的全局与目录指令 |
| 新增重型工具、更换工具来源等需要重新挂载的能力 | 释放并恢复会话后挂载，界面会提示待恢复能力 |
| 修改 MCP 服务器 | 释放并恢复会话的 Agent 后挂载；界面会提示待恢复能力 |
| 停用或删除预设 | 空白会话即时重绑；已开始的会话下次恢复使用回退预设 |

「释放并恢复」是让 DSH 重新创建该会话的运行实例，聊天记录保留。保存配置不会回写已发送的请求、清除历史上下文或撤销已执行的操作；保存与恢复默认也无法撤销已经执行的操作。

预览展示新配置，不代表旧会话已经获得全部新能力。若要比较两套预设的效果，建议分别使用新会话，减少旧上下文的影响。

**工具开关控制模型可见的能力；实际访问权限、沙箱与审批仍由 DSH 和来源插件执行。** 工坊可以展示这些策略，权限变更应通过宿主提供的设置完成。

<details>
<summary><b>来源与能力边界</b></summary>

- **第三方工具**：只能发现实际已注册的能力；来源插件未启用的工具，需先在来源侧启用，工坊不会凭空启用，也不代改来源配置。
- **代理层**：例如已核对的 `billion-context` 压缩指令来自代理转发层，未提供 DSH 读取／覆盖接口，工坊会说明边界，无法预览、编辑或排序这些内容。
- **MCP**：预设自建的服务器只在该预设内生效，停用／删除即随之释放；全局扫描只读取宿主 profile 已注册的 MCP；连接离线时保留已保存工具的「不可用」状态，不伪造可调用的 schema。
- **模型与权限**：读取所选环境的实际策略，当前不提供预设级模型或权限绑定。工具选择不等于安全沙箱，权限与审批继续由 DSH 和来源插件执行。

</details>

## 数据与卸载

配置保存在宿主数据目录下，默认位置为 `~/.dsh/preset-workshop/`；设置了 `DSH_HOME` 时跟随该位置。

<details>
<summary><b>配置文件位置</b></summary>

```text
<DSH_HOME>/preset-workshop/
├─ config.json                 设置与预设索引
├─ catalog.json                工具发现缓存
└─ presets/<id>/
   ├─ preset.json              名称、描述、状态、技能与 MCP
   ├─ prompt.json              人设、系统段与全局 AGENTS 覆盖
   └─ tools.json               工具选择、描述与使用指令覆盖
```

业务数据与插件代码分离。保存采用文件锁、原子写入和恢复机制，并检查并发修改冲突。需要分享或备份配置时，可使用导出功能。

</details>

**卸载前，请先处理仍依赖工坊预设的会话。** 将需要保留的会话迁移到插件卸载后仍存在、可解析的宿主预设，并确认能够恢复。工坊内部的回退预设仍依赖本插件，不能替代这一步。

然后按安装时使用的 profile 卸载：

```sh
# 官方桌面端
dsh plugin --profile desktop remove dsh-preset-workshop

# dsh web
dsh plugin --profile web remove dsh-preset-workshop
```

卸载保留预设业务数据。如需手动清理数据目录，请先备份。
